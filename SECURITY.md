# Security Policy

## Our Commitment

Security is a core principle of PDFOptimizer. We continuously work to provide a secure environment for users and protect their documents throughout the processing workflow.

## Responsible Disclosure

If you believe you have discovered a security vulnerability related to PDFOptimizer, we encourage you to report it responsibly.

Please include as much information as possible, such as:

- A detailed description of the vulnerability.
- Steps to reproduce the issue.
- A proof of concept, if available.
- The potential impact.

Please do not publicly disclose security issues until they have been reviewed.

## What to Report

Examples of security issues include, but are not limited to:

- Remote code execution
- Authentication or authorization issues
- Cross-Site Scripting (XSS)
- Cross-Site Request Forgery (CSRF)
- SQL Injection
- Server misconfigurations
- Sensitive data exposure
- Security issues affecting document processing

## What Not to Report

The following generally do not qualify as security vulnerabilities:

- Browser-specific behavior outside our control.
- Issues requiring unrealistic user interaction.
- Missing HTTP security headers with no practical impact.
- Outdated browser versions that are no longer supported.

## Privacy

For supported tools, document processing is performed locally in the browser whenever possible. When server-side processing is required, files are handled according to our Privacy Policy.

## Response Process

After receiving a valid security report, we will:

1. Review the report.
2. Validate the issue.
3. Investigate its impact.
4. Deploy a fix when appropriate.
5. Update affected systems if necessary.

We appreciate responsible security research that helps improve PDFOptimizer for everyone.
